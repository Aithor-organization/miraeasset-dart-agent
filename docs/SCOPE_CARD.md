# 공시 Agent 업무 범위 카드 (Scope Card)

> 이 문서는 공시 Agent의 자율성·데이터·품질 경계를 고정하는 운영 계약이다. 기능을 추가하거나 모델·인덱스·배포를 바꾸기 전에 이 카드와 골든셋을 함께 갱신한다.

## 1. 범위

| 항목 | 계약 |
|---|---|
| 사용자 | 공모전 평가 시스템과 DART 공시를 조회·비교하려는 금융 분석 사용자. 익명·읽기 전용 접근만 허용한다. |
| 단일 핵심 업무 | 지정 코퍼스의 DART 공시를 검색·비교·계산하고, 출처와 한계를 포함해 설명한다. |
| 데이터 범위 | 저장된 DART 코퍼스의 대상 기업·기간·문서 유형만 사용한다. 외부 뉴스·웹·리포트는 답변 근거로 사용하지 않는다. |
| 부수효과 | 없음. 데이터·계정·자금·외부 시스템을 변경하지 않는다. |
| 책임자 | 제출자 본인. 코드·인덱스·프롬프트·평가 산출물·배포 버전의 최종 승인자다. |

## 2. 권한과 자율성 경계

| 영역 | 책임 주체 | 허용 범위 |
|---|---|---|
| 사실 조회·계산·정정 체인 | SQLite·도구 코드 | 결정론적으로 실행한다. LLM이 수치나 계산 operand를 생성하지 않는다. |
| 기권·안전 검증 | 규칙 기반 검증기 | 근거 부족, 기간 밖, 예측·투자판단, PII 요청은 응답을 제한하거나 기권한다. |
| 목차 주소 선택 | Low effort LLM 보강 | 규칙이 실패한 경우만 사용하고, 반환값은 법정 목차 화이트리스트로 제한한다. |
| 문장 다듬기 | Low effort LLM 보강 | 이미 확정된 본문만 입력한다. 검증 실패·장애 시 결정론 템플릿으로 강등한다. |
| High effort 추론 | 사용하지 않음 | 시장 전망·전략 판단·외부 리서치는 이 Agent의 업무가 아니다. |
| 인간 승인 (HITL) | 현재 N/A | 읽기 전용 API에는 승인할 부수효과가 없다. 리포트 발행, 투자 의사결정 지원, 데이터 변경 기능을 추가하면 승인 지점을 먼저 설계한다. |

## 3. 자동 금지와 데이터 경계

- 미래 실적·주가 예측, 매수·매도·목표주가·추천을 생성하지 않는다.
- 개인 식별정보, 계좌·결제 정보, 비밀값을 출력하거나 외부 모델에 전송하지 않는다.
- PII/secret 요청은 질의 해석·도구 조회·LLM 호출 전에 차단한다.
- HyperCLOVA X 허용 endpoint와 HCX 계열 모델만 사용한다. 다른 provider·endpoint·모델명은 fail-closed로 거부한다.
- MCP는 현재 사용하지 않는다. 내부 SQLite 도구만으로 충분하며, 공유·원격 도구를 도입할 때만 별도 보안 검토 후 재평가한다.

## 4. 성공 기준과 릴리스 게이트

| 지표 | 기준 | 검증 방법 |
|---|---:|---|
| 계약 유지 | API 필수 5필드 100% | 단위·HTTP E2E 테스트 |
| 안전 위반 | 골든셋 기준 critical violation 0건 | safety·regression 테스트 |
| 사실 품질 | 독립 검수 골든셋 기준선 이상 | `eval/score.py` |
| 지연 | p95 240초 이하, 평가 타임아웃 300초 초과 0건 | cold-cache 부하 측정 |
| 비용 | 문항당 4,000 토큰 이하 | provider 사용량 기록 |
| 모델 변경 | 품질·안전·지연·비용 회귀 없음 | 모델 변경 전/후 동일 골든셋 비교 |

현재 저장소에 운영 인덱스가 없으면 인덱스 의존 골든셋·부하 측정은 **미검증**으로 기록하며, 과거 실행 결과를 현재 릴리스의 성능으로 선언하지 않는다. baseline은 `eval/baseline/v1.0.0/manifest.json`의 hash와 문항 수를 먼저 검증한다.

## 5. 관측·운영 통제

요청별 `trace_id`와 비가역적 원문 대신 `question_hash`를 기록한다. 로그는 기록 시점에 PII·자격증명·연락처를 마스킹한다. `/ready.runtime`에는 요청·기권·강등·LLM 호출·429·토큰 카운터를 노출한다. 외부 uptime monitor는 `/ready`를 30초 주기로 확인하고 연속 3회 실패 시 재시작·알림한다.

현재 서비스는 동기식 읽기 전용이므로 DLQ, 영속 멱등성 원장, fan-out/delegation cap, HITL/Draft-First는 적용 대상이 아니다. 쓰기·비동기·멀티테넌트 기능을 추가하는 즉시 P0로 승격한다.

## 6. 버전 및 표현 규칙

릴리스 기록에는 코드 commit, 인덱스 hash, 골든셋 버전, 프롬프트 hash, 요청 모델 ID와 응답 모델 ID, 실행 일시를 남긴다.

다음 절대 표현은 검증 범위를 붙여서만 사용한다.

| 피할 표현 | 권장 표현 |
|---|---|
| 환각 발생 불가 | 수치·계산 경로는 결정론적으로 제한하며, 비수치 서술은 검증기와 회귀 테스트로 관리한다. |
| 오판율 0% | 확정된 N개 골든셋에서 critical error 0건. |
| 모델을 고정했다 | 요청 모델 ID를 고정했으며, provider revision 변화는 평가 게이트로 감시한다. |
| Context Caching | provider context cache와 애플리케이션 응답 캐시를 구분해 명시한다. |
| 제약 디코딩 | grammar/schema decoding인지, 출력 후 결정론 검증인지 구분해 명시한다. |
