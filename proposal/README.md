## 한 문단 요약

공시의 **숫자는 조회하고 문장은 생성한다.** DART XML은 재무제표 셀에 XBRL 인라인 태깅
(`<TE ACODE="dart_OperatingIncomeLoss" ACONTEXT="CFY2024dFY_…ConsolidatedMember">`)을 갖고 있고,
계약·지분·자금조달 공시는 완전 정형이며, 정기공시는 동일 법정 목차를 따르고, 정정공시는
원본 포인터와 정정전/후 diff 표를 스스로 담는다. 그래서 우리는 LLM에게 표를 읽히지 않고
**먼저 사실로 정규화한 뒤** 해석과 설명만 맡긴다. 수치는 LLM이 생성할 수 없고
(`{{fact_id.value}}` 자리표시자 → 서버 치환), LLM을 쓰지 않는 결정론 검증기 5종을 통과해야
응답이 나간다. 환각을 탐지하는 대신 **발생 불가**로 만드는 설계다.

## 핵심 실측 사실 (전부 본 코퍼스에서 직접 확인)

| 사실 | 값 |
|---|---|
| 코퍼스 | 4,204문서 / 4,616 XML / **5.3GB** / 70개사 / 2023.01~2026.03 |
| 텍스트 총량 | ≈ **400M chars** — 그중 **95%가 정기공시** |
| 거래소공시 포맷 함정 | 1,469건 전부 **HTML**이며 meta는 `euc-kr` 선언, **바이트는 UTF-8** |
| 거래소공시 정정 비율 | **43%** (631/1,469) — 미처리 시 집계 과대계상 |
| XBRL 태깅률 | annual **60%** / half **28%** / quarter **28%** (표본 기준) → 표 파싱 폴백 필수 |
| 목차 안정성 | 12개사·10섹터 표본 **12/12** 핵심 5섹션 보유 |
| 정기공시 볼륨 편중 | 상위 7개 섹션(**47%**)이 인명·계열사 레지스트리 표 → 임베딩 제외 대상 |
| **금액 단위 혼용** | 원 / 천원 / 백만원 혼용 + 표본 **27% 미표기** → 정규화 없으면 비교 질의 **1,000배 오차** |

## 설계의 외부 검증

「주소 우선, 검색은 나중」(D2)은 우리가 코퍼스 실측에서 독립적으로 도달했으나, 사내
`AI-research-SKILLs/15-rag/pageindex`가 동일 사상(**Vectorless RAG**)으로 **FinanceBench 98.7%**
(벡터 RAG 80~90%)를 보고한다. 그리고 PageIndex의 주 비용인 **LLM 트리 인덱싱**을 본 코퍼스는
회피한다 — `<TITLE>` 법정 목차가 트리를 이미 제공하므로 결정론적 파싱으로 끝난다.
(98.7%는 영문·타 모델 기준이라 한국어 전이는 `[추정]`이며, 라이브러리는 HCX 제약상 미사용 — 사상만 차용.)
