### SPEC에 추가할 문장 (복붙용) — `specs/SPEC.md` §11로 신설

```markdown
## 11. 서술·라우팅 계층 계약 (LLM 사용 경로)

### 11-1. 서술 계층 (`agent/narrate.py`)

**AC-N1** `narrate()`는 이미 확정된 답변 본문만 입력받는다. 원자료·DB·검색 결과에
접근하지 않는다. LLM은 *다시 쓰기*만 하며 *조회·계산*은 하지 않는다 (D1 후반부).

**AC-N2** 서술본의 `(수치, 단위)` 쌍 집합은 원본과 완전 일치해야 채택된다.
정확한 값 바로 뒤 괄호의 파생 환산 표기는 **누락만** 면제하며, 신규 생성은 면제하지 않는다.

**AC-N3** 서술본에 원본 본문·질문 어디에도 없는 내용어가 있으면 거부한다 (덧붙이기 금지).

**AC-N4** 서술본은 원본의 다음 요소를 **전부 보존**해야 한다. 소실·반전 시 원본 템플릿으로 강등한다.
  - 기준어: `연결기준` `별도기준` `누적` `당기`
  - 부정·미해결 표시: `확인되지 않` `해당 없` `미해소` `제외했습니다`
  - 회계 기간 조건절: `20\d{2}년` `제N기` `N분기` `N월`
  검사는 집합 차집합이 아니라 **토큰별 존재 검사**로 구현한다 (차집합은 삭제·반전을 원리적으로 검출하지 못함).

**AC-N5** 원본에 없던 hedging(예상·추정·전망) 또는 편집 메타 주석이 서술본에 나타나면 거부한다.

**AC-N6** 강등이 발생하면 그 사유를 `think_trace`에 1줄 기록한다. 침묵 폴백 금지.

**AC-N7** LLM 전 계층을 차단한 상태에서 골드셋 점수가 유지되어야 한다.
LLM은 품질 향상 요소이지 정답 생성 주체가 아니다.

### 11-2. 목차 라우팅 (`agent/route_section.py`)

**AC-N8** LLM이 반환한 섹션 주소는 `CATALOG` 화이트리스트를 통과한 것만 사용한다.
카탈로그 밖 주소는 폐기하고 로그로 남긴다. 최대 2개.

**AC-N9** 규칙(`INTENT_PATHS`)이 주소를 찾은 질의에서는 LLM을 호출하지 않는다.

### 11-3. 레이트리밋 (`llm/ratelimit.py`)

**AC-N10** CLOVA 429 수신 시 응답 헤더가 지시한 리셋 시간만큼 대기 후 재시도한다.
잔여 토큰이 임계 이하이면 선제 대기한다.

**AC-N11** 재시도가 소진되면 결정론 템플릿으로 강등한다. 5xx 전파 금지 (AC-API2와 동일 원칙).
```

| **회계연도 조건절 삭제** (`2024년 `) | 🔴 통과 — `:31` `_YEAR`가 비교에서 제외하므로 구조적 사각 |

### 🔴 신규 가드의 구조적 한계 2가지 (실측 확정)

**① 집합 차집합이라 덧붙이기만 잡는다.** `_new_content()`는 `_content_words(out) - _content_words(body|question)`(`:166`)이므로 **삭제·반전은 원리적으로 검출 불가**(부분집합이 되어 차집합이 공집합). 경계 실험으로 확정:

- 본문에 `별도`가 **없으면** 연결→별도 변조 차단 (`미근거 내용 주입(별도)`)
- 본문에 `별도`가 **이미 있으면**(연결/별도 병기 답변) → **통과**
- 부정 반전은 어간 `확인`이 원본과 공유되어 **항상 통과**

**② 질문 화이트리스트가 새 구멍을 냈다.** 질문 어절이 허용 집합에 포함되어(`:151` `question` 파라미터), **질문의 프레이밍을 그대로 단정문으로 되받는 주장**이 통과한다:

```
질문: "삼성전자의 2024년 실적이 개선되고 수익성이 회복되었는가?"
본문: "…매출액은 300,870,903백만원입니다 [C1]."
서술: "…매출액은 300,870,903백만원입니다 [C1]. 실적이 개선되고 수익성이 회복되었습니다."
→ 통과 🔴  (모든 내용어가 질문에서 왔으므로 신규 아님)
```

근거 없는 판단이 질문을 매개로 답변에 주입된다. 유도형 질문("~가 유망한가?")에서 특히 위험하다.

> 하류 `verify()`는 `orchestrator.py:423`에서 narrate(`:388`) **이후** 실행되지만,
> V1은 숫자·V4는 금지어 정규식이라 위 6종 + 질문 되받기를 모두 못 잡는다.

### 1. 🔴 SPEC §11 신설 + `narrate`에 AC-N4 보존 검사 추가

### 2. 🔴 README 수치 3건 정정
`232 → 242` (§8) · `104 tests → 242` (§7) · `수기 16종 → 24종` (§4). SPEC AC-A3(8종)도 24종으로 동기화. 심사위원이 `pytest`를 한 번만 돌려도 드러나며, **정확성을 파는 제출작에서 자기 문서 숫자가 틀린 것**은 다른 모든 수치의 신뢰를 함께 깎는다.

### 3. AC-API4 결정 — 구현하거나 삭제하거나
25초 타임아웃을 실제 구현하고 테스트를 붙이거나, SPEC에서 삭제하고 실제 운영값(README §6 부하시험 300초)으로 대체한다. 현재는 "명세에 있는데 코드에 없는 MUST" = Key Gate 2건 동시 FAIL의 단일 원인이다.
